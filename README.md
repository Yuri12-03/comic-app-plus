# まんがのわ

スマホ優先の漫画管理アプリ。トップページ、メール・パスワードによる新規登録、自動ログイン、ログアウト、自分の本棚の一覧・作品詳細、ISBNからの漫画登録を実装しています。友達の登録・承認と友達の本棚閲覧も実装しています。貸出は今後追加します。

## 起動・接続

`npm install` の後、`npm run dev -- --port 3001` を実行し、http://localhost:3001 を開きます。
`.env.example` を `.env.local` にコピーし、SupabaseのProject URLとPublishable keyを設定します。接続設定はGitHubに含めません。
Vercelでは同じ環境変数を設定し、変更後に再デプロイしてください。

## 認証設定

SupabaseのAuthentication → Sign In / ProvidersでEmailを有効、Allow new users to sign upをオン、Confirm emailをオフにします。
登録すると確認メールを介さずログインします。入力したメールアドレスの所有確認は行いません。
SMTPと確認メールテンプレートの設定はこのフローには不要です。

## ユーザーの保存先

Supabaseの `auth.users` にユーザーID・メールアドレス・ハッシュ化されたパスワード等を保存します。Authentication → Usersで確認できます。
`public.profiles`等のプロフィールテーブルはまだ作成していません。

## 検証

`npm run lint` と `npm run build` で検証します。
新規登録 → 自動ログイン → 再読み込み → ログアウト → 再ログインと、Supabaseのユーザー一覧への反映を確認します。
未ログインの `/account` は `/login` に移動します。

Cookieによる認証と検証済みのJWT claimsを使用します。

## 自分の本棚

ログイン後の「自分の本棚」から `/account/bookshelf` を開きます。
作品ごとに、所持する巻のうち巻数が最も小さい巻の表紙を表示します（例：3・5・10巻なら3巻）。表紙がない・取得できない場合は、その巻の代替表示を出します。カードを押すと作品紹介・著者・所持巻・ISBNを確認できます。
同じ巻を複数冊持つ場合も冊数に含め、所持巻の表示は重複をまとめます。漫画が未登録の作品は一覧に出しません。

`?preview=1` は架空の作品で配置を確認するサンプル表示です。ログインが必要で、データベースへの保存は行いません。

`supabase/migrations/202610100001_personal_bookshelf.sql` をSupabaseのSQL Editorで一度実行します（現在のプロジェクトには適用済み）。
`bookshelves` → `comic_series` → `comic_copies` の外部キーで各冊の所属本棚を一意に保ちます。現在は個人本棚のみで、承認済みの友達は個人本棚の公開作品を閲覧できます。グループは今後拡張します。
3テーブルすべてにRLSを有効にし、認証ユーザー本人の本棚だけを読み取り・追加できます。未認証ユーザーにアクセス権はなく、他人の本棚への書き込みも拒否します。更新・削除の権限はまだ付与していません。

`npm run test:bookshelf` で最小巻選択・数値順・重複冊数・表紙欠損を検証します。
`supabase/tests/personal_bookshelf.sql` は既存の2つのテスト用Authユーザーを使い、所有者分離と未認証アクセス拒否を検証します。テストの本棚・漫画はトランザクション終了時にロールバックされます。

## ISBNから漫画を登録

ホームの「漫画を登録」または本棚の「＋ 漫画を登録」から開きます。
カメラ・写真のEAN-13バーコードを端末内のZXingで読み取り、ISBNだけをサーバーに送信します。カメラはHTTPS（またはlocalhost）とブラウザのカメラ許可が必要です。978/979以外の価格バーコードは登録に使いません。ISBNの手入力（10桁、13桁、ハイフン、全角数字）にも対応します。

書誌情報はopenBD、表紙はopenBDまたはOpen Libraryを使用します。ISBNが一致する情報だけを採用します。
`GOOGLE_BOOKS_API_KEY` をサーバー環境変数に設定すると、両者に書誌がない場合にGoogle Booksを補完に使います（任意、NEXT_PUBLICにはしません）。
情報が見つからない・サービス停止中の場合は手入力できます。取得できない表紙は空欄で登録可能です。
巻数と作品名の推定結果を確認して保存します。既存作品を選んで各巻をまとめることもできます。

`supabase/migrations/202610100002_register_comic.sql` を一度実行します（現在のプロジェクトには適用済み）。
RLSを適用する `security invoker` の `register_comic` 関数で、本棚・作品・巻を1トランザクションで追加します。ISBNのチェックデジット・各入力の上限を確認し、登録トークンで再送を冪等に扱います。同じISBNは通常拒否し、複数冊所持を明示した場合だけ追加します。
各巻に書名・出版社・刊行情報・書誌の出典・元のAPI取得情報を保存します。ユーザーが編集する作品名等は、APIの元情報と分けて保持します。表紙画像はURLを保存し、画像ファイルの転載保存は行いません。

`npm run test:registration` でISBN検証、巻数推定、API補完・不一致・通信失敗、EAN-13のデコードを検証します。
`supabase/tests/register_comic.sql` は保存の原子性・再送・重複・既存作品への追加・他人の本棚への書き込み拒否を検証し、テストデータはロールバックします。

## 巻数の範囲で追加

1冊のISBNを検索したあと「巻数の範囲で追加」を選び、開始巻・終了巻を指定します（一度に50冊まで）。国立国会図書館サーチのSRU APIから作品名・著者・出版社を使って各巻のISBNを探します。漢数字の巻次、副題付き巻次、Vol.表記も読み取ります。
候補が複数ある巻はブラウザで各候補の表紙を実際に読み込み、表示できる候補を初期選択します（1画像につき最大4秒）。複数の表紙が表示できる場合は候補順で選び、すべて読み込めない場合は未選択にします。利用者はISBNを選び直せます。情報がない巻は除外して表示し、架空のISBN・表紙は生成しません。各巻を追加しない選択もできます。検索は公開書誌だけをキャッシュし、検索結果上限500件のため全巻の発見を保証しません。表紙が見つからない場合は代替表示になります。

`supabase/migrations/202610110001_register_comic_range.sql` を一度適用します（現在のプロジェクトには適用済み）。`register_comic_batch` は既存の所有者確認・ISBN検証・重複検出を利用し、選択した巻を1トランザクションで保存します。途中の失敗は全冊ロールバックされ、同じ登録トークンの再送は二重保存しません。
`supabase/tests/register_comic_batch.sql` で一括保存・再送・途中失敗・重複拒否を検証します。

## ユーザー情報と初回設定

新規登録ではプロフィール設定を挟み、ユーザーネームとアイコンを保存してからホームへ進みます。途中で離れた場合も、次回ログイン時に設定へ戻ります。既存ユーザーはホームの「設定」→「ユーザー情報」で登録・変更できます。
名前は1〜30文字の表示名（重複可）です。8種類のデフォルトアイコン、またはJPEG・PNG・WebPの写真を選べます。写真は端末内で中央を256×256に切り抜きJPEGへ変換し、変換後の画像だけを送信します。入力写真は15MB以下、保存画像は512KB以下です。

`supabase/migrations/202610110002_user_profiles.sql` は適用済みです。`user_profiles` と非公開の `profile-photos` バケットを作成しました。本人だけがプロフィールを読み取り・登録・更新でき、写真も本人のフォルダーだけが読み取り・追加・削除できます。ホームと編集画面は有効期限付きの写真URLを取得します。写真の変更に失敗したときは以前の設定を保持します。

`npm run test:profile` で名前・アイコン・画像の実形式を検証します。`supabase/tests/user_profiles.sql` は作成・変更・入力制限・所有者分離を検証し、テストデータをロールバックします。

## フレンドID・QRコードと相互承認

ホームの「友達管理」で自分のフレンドIDとQRコードを表示し、相手のID入力・カメラ・QRの写真から申請します。相手を確認して申請し、受信側の承認後だけ双方の一覧に表示します。送信済み・受信済みの申請は友達管理で確認できます。「友達の本棚」の一覧から、友達の公開作品と作品詳細・所持巻を閲覧できます。

`supabase/migrations/202610110003_friends.sql` は適用済みです。既存・新規のAuthユーザーに16桁のランダムなフレンドIDを発行します。IDは検索用識別子で認証情報ではありません。申請関係はユーザーの組ごとに1件だけ保存し、再送や逆方向の申請でも重複しません。申請者自身や第三者が承認する操作は拒否します。名前は本人のプロフィールから表示し、メールアドレスは友達検索や一覧に返しません。写真は承認済みの相手にだけ読み取りを許可し、本棚は閲覧専用の関数で承認済みの友達に公開します。

QRには公開サイトの相手確認URLを埋め込みます。URLを開いただけでは申請しません。ログイン・初回プロフィール設定を経ても相手確認画面へ戻ります。ログインの戻り先は有効なフレンド確認URLに限定しています。`npm run test:friends` でフレンドID・URL検証と生成QRのZXingによるデコードを確認し、`supabase/tests/friends.sql` で申請・見送り・再送・相互承認・他人の操作拒否を検証します。

## 友達の本棚

supabase/migrations/202610110004_friend_bookshelves.sql は適用済みです。read_friend_bookshelf は毎回承認済みの関係を確認し、個人本棚の公開作品・全冊の書誌情報を返します。匿名・未承認・第三者のアクセスは拒否します。本人用のテーブル読み取り・登録権限は変更していません。supabase/tests/friend_bookshelves.sql で検証します。

## 公開・おすすめ設定

supabase/migrations/202610110005_comic_visibility.sql は適用済みです。既存・新規の作品は初期状態が公開、おすすめは未設定です。本人の作品一覧で公開状態とおすすめを切り替えます。設定変更は所有者だけに許可し、友達への読み取り関数では非公開作品を除外し、おすすめを先頭に並べます。非公開作品の詳細URLも閲覧できません。非公開にしてもおすすめ設定は保持され、再公開時に反映されます。supabase/tests/comic_visibility.sql で検証します。

## 漫画名で検索

漫画登録画面でISBNと漫画名検索を切り替えられます。NDLサーチのタイトル検索から、作品名・著者・出版社ごとに候補をまとめ、表紙情報を補完します。候補を選ぶと巻数指定へ進み、1冊だけの登録も選べます。NDLにのみ書誌情報があるISBNも、巻検索の際に再取得して使用します。検索・確認だけでは保存せず、既存の重複確認・一括登録処理を使用します。
